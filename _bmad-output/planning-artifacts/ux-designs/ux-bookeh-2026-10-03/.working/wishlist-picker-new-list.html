Wishlist picker, no lists yet

Story 7.14 [H10]. Add to wishlist opens the wishlist picker (a bottom sheet on the phone, a dialog on wide screens); with one list it is skipped. With no lists it offers only "New list". How that list gets its name has to stay inside this one overlay, because overlays go one deep: no New list dialog on top of the picker sheet. Three ways. The scenario: Mika scans Sinuhe egyptiläinen in a shop, Not in library, and he has never made a wishlist. Strings in English; Finnish follows the same layout.

In every option the new list is created inside the save's transaction (a { create: name } Ref), a name already in use is rejected under the field and the overlay stays open, and Undo on "Added to {list} · Undo" removes the entry but keeps the list.

A · Name field under the rows

The Move picker as it is. Rows of lists, then a New list Text field with a secondary Add button beside it, disabled while the field is blank. With no lists, the rows are simply absent and the field is focused on open with the keyboard up. One pattern for both cases, nothing to learn, and already built for locations. A new list is one Add away even when lists exist.

B · New list turns into a field

The picker stays a list of choices. With no lists it says No wishlists (the empty state EXPERIENCE.md already names) and shows one row, New list.
