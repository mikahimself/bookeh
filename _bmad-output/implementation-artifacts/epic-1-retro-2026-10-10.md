### Diff-scope review (bmad-review: adversarial, edge-case, verification-gap lenses)

Three lenses ran over the full epic diff (lockfile, generated migration JSON and `_bmad-output` excluded — narrowing recorded). Findings merged across lenses; where two lenses hit the same defect independently, both are credited — overlap is confirmation.

**Confirmed defect (verified by the retro directly):**

- **R1. Flash-toast cookie is double-encoded on the wire and single-decoded on the client** — `flash.ts:16` calls `encodeFlash` (one `encodeURIComponent`) and Next's `cookies().set` encodes again; `takeFlash` reads raw `document.cookie` and `decodeFlash` (`flashCookie.ts:53`) decodes once, so `JSON.parse` fails and returns `null` after the cookie is already cleared. The prefs cookie compensates with a matching double decode (`prefs.ts:69`, e2e comment "Next encodes once more on set"); the flash pair was built on mismatched wire assumptions. Latent only because nothing calls `flashToast()` yet — the Epic 3 scan-save flow is its intended first consumer, and every server-raised toast would be silently swallowed. The only tests are mock-call and single-encoded-value tests (`tests/unit/flashCookie.unit.spec.ts:15-106`); no test crosses real serialization. Source: verification-gap lens findings 1–2, confirmed by direct code read in this retro. *Disposition: fix-now, with a round-trip e2e/int test pinning the chosen contract.*

**Boundary and robustness findings (fix or defer):**

- **R2. Task close breaks at the browser history cap** — `navigation.ts:36-45` compares `window.history.length` to a recorded load length; browsers cap length at 50, so in a long-lived PWA session (exactly the scan-many-books flow) the X stops going back and always replaces to `/`. Found independently by both adversarial (#1) and edge-case (#1) lenses. *Disposition: fix before/with Epic 3's scan task (story 3.1 relies on this close).*
- **R3. Settings switch revert race** — `ThemeSwitch.tsx:31-42` (same pattern in LanguageSwitch, VisibilitySwitch): two quick taps where the first action settles late revert state to a stale `previous`, leaving the pressed option/`data-theme` disagreeing with the stored value. Both lenses (adv #4, ec #2). *Disposition: fix-now (request-sequence guard, small).*
- **R4. Seed race on concurrent first boot** — `seedFirstUser.ts:11-13` count-then-create: two processes on an empty DB both create; the loser throws out of `onInit` and aborts boot — precisely the LXC compose bring-up moment. Both lenses (adv #14, ec #10). *Disposition: fix-now (catch unique violation); ties into spec-recon #5.*
- **R5. CI drift check rests on grepping one Payload log line** — `ci.yml:85-99`; a Payload bump that rewords "Migration DOWN statements generation complete" silently turns the schema-drift gate into a no-op (or makes every run fail). Both lenses (adv #13, ec claim). *Disposition: action item (assert postcondition directly).*
- **R6. E2E lane validates push-built schema, not migrations** — `ci.yml:120-121`: only the int lane runs against the migration-built DB; a migration defect that push silently repairs passes e2e green. Adversarial #9; same ground as spec-recon #2 (e2e on dev DB, deferred to 3.52). *Disposition: defer to 3.52, but noted that the drift-gate's coverage has a second hole beyond the recorded one.*
- **R7. Swipe suspension can leak** — `swipe.ts:37-56`: module-level `holds` counter decremented only by effect cleanup; an abnormal unmount leaks a hold and swiping dies until reload, silently. Adversarial #3. *Disposition: defer with a note on the 3.40/3.41 overlay stories, which add more holders.*
- **R8. Stale-pathname double swipe** — `swipe.ts:180-206` computes the target from `usePathname()`, so a second swipe before the push lands advances from the stale section. Edge-case #6. *Disposition: defer (cosmetic mis-navigation).*
- **R9. `useReportFailure` hardcodes `next=%2Fsettings`** — `settings/report.ts:19-24` reads as generic and will be reused by the next section's controls, bouncing users to /settings after re-auth. Adversarial #6; compounds the aggregate-view duplication finding on `settled()`. *Disposition: fix-now while extracting the shared client helper.*
- **R10. Gateway "writes by ID only" is type-level only** — `gateway.ts:54-71` picks the last overload of `payload.update`/`delete`; a Payload bump reordering overloads could re-admit `where` writes with nothing failing. Adversarial #10. *Disposition: fix-now (one runtime guard line).*
- **R11. `displayName` has no length/control-character cap** — `profile.ts:52-58` trims and NFC-normalises but stores unbounded input. Edge-case #4. *Disposition: fix-now (server-side cap).*
- **R12. Cookies never `secure`** — `prefs.ts:80-86`, `flash.ts:17-22`, and the session cookie (already in spec-recon #3). Adversarial #8. *Disposition: defer with hard gate at Epic 2.*
- **R13. Every e2e user is an admin** — `tests/helpers/seedUser.ts` hardcodes `roles: ['admin','user']`, so no e2e flow runs as a plain user; a user-role frontend regression would pass. Edge-case deletion finding. *Disposition: fix-now in tests (default to `user`, opt into admin).*
- **R14. Client-lib import rule has a barrel loophole** — `eslint.config.mjs` zones don't cover a re-export barrel in `src/app/**` laundering `src/lib` into client bundles. Adversarial #12; compounds the aggregate-view finding on the untested custom rule. *Disposition: action item with the lint-rule hardening.*
- **R15. Visibility switch accessibility naming collision** — `VisibilitySwitch.tsx:49-61`: group named "Profile" collides with the `<h2>Profile</h2>`; visible label associated with nothing. Adversarial #11. *Disposition: fix-now (small).*
- **R16. Minor edge cases, recorded for later touches:** whitespace-only password can never sign in (`session.ts:11`, ec #8); proxy matcher's dot-segment exclusion loses `?next` for future dotted routes and leaves the path header one validation hop deep (`proxy.ts:19-21`, adv #2 + ec #9); `SWIPE_WIDE_PX`/`--breakpoint-wide` 900 pair has no pinning test (ec #7); double-tap on the task X can call `router.back()` twice (ec #3); flash cookie set without a following navigation fires stale up to 60 s later (adv #7 — the restriction is documented in `flash.ts` but unenforced). *Disposition: accept/defer individually; none blocks acceptance.*

**Verification-gap lens otherwise clean:** the lens explicitly reported Epic 1's behaviors unusually well pinned across story boundaries (users access incl. role-escalation drops, gateway scope enforcement with a control test, session lifecycle incl. lockout, locale precedence end to end, device-prefs double-encoding verified in a real browser, drift checks, shell/swipe/task flows in real-browser e2e) — the flash cookie is the one contract no test crosses.

## Action items

All are **proposed remediation** for the normal dev loop — nothing was auto-applied. Owner is Mika (solo project); "story-shaped" items should enter the backlog rather than be done ad hoc.

1. **Fix the flash-toast cookie contract** (R1): make encode/decode symmetric across Next's extra encode, and pin it with a round-trip test through real serialization. Must land before Epic 3's scan-save flow adopts `flashToast()`.
2. **Fix the settings switch revert race** (R3): per-control request sequence; ignore stale settles in ThemeSwitch, LanguageSwitch, VisibilitySwitch.
3. **Guard the first-user seed against concurrent init** (R4 + spec-recon #5): catch unique violation as "already seeded"; consider retrying a failed first init. Relevant to Epic 2's LXC bring-up.
4. **Extract a shared client action-failure helper** (R9 + aggregate duplication): move `settled`/`useReportFailure` out of `(sections)/settings/report.ts`, derive the re-auth `next` from `usePathname()`, reuse in SignOutButton and LoginForm; dedupe `isPlainObject`/tuple-membership guards between `prefs.ts` and `profileChanges.ts`; decide one error presentation (toast vs inline) for action failures.
5. **Add a runtime by-ID guard to gateway writes** (R10): one `if ('where' in options) throw` in `updateByID`/`deleteByID`.
6. **Cap `displayName` server-side** (R11): length limit + control-character rejection in `lib/account/profile.ts`.
7. **Default e2e seed users to `user` role** (R13): `tests/helpers/seedUser.ts` opt into admin only where /admin is tested.
8. **Harden the CI drift check** (R5): assert the postcondition (no `*_ci_drift_check.*` file + clean `git status`) instead of grepping a Payload log line.
9. **Fix the admin e2e URL assertion** (behavior check): tolerate Payload's `?depth=1&limit=10` query string in `tests/e2e/admin.e2e.spec.ts:30`.
10. **Fix task-close before Epic 3's scan task** (R2): stop comparing `window.history.length` (capped at 50); track in-app entries directly. Also debounce the double-tap on the X (ec #3).
11. **Own the deferred security items with an Epic 2 gate** (spec-recon #1, #3; R12): own email/password changeable over REST without current password; session/prefs/flash cookies never `Secure`; sign-in timing leak. Acceptable on the tailnet; must be resolved or explicitly re-accepted before Epic 2's production deploy.
12. **Fix the visibility switch group naming** (R15): distinct accessible names, label association.
13. **Pin the compose app image** (spec-recon #8): `docker-compose.yml` still `node:22-alpine`; pin to 22.23.3 or fold into Epic 2's image story.
14. **Process lesson — review Story 3.52's scope at Epic 3 planning:** it now carries the e2e-database move plus deferred browser-verification for login, toasts, and fonts (spec-recon #7, R6). Split it if it has become an epic-sized catch-all.
15. **Process lesson — lint enforcement needs its own tests** (R14 + aggregate): the custom `clientLibImports` rule and zones are untested and have a barrel loophole; add fixture-based lint tests or extract the rule.
16. **Close the REST self-update of email and password** (decision 2): a non-admin cannot change their own `email` or `password` through `PATCH /api/users/<own id>` (field-level `update` access); prove it with a two-user access test.

It was not written anywhere story sessions read it, and the spine's Playwright limit was overridden in five stories (1.5, 1.19, 1.20, 1.21, 1.23 added 40 of the 45 e2e tests). ## Decisions (Mika, 2026-10-10)

1. **Sign-out failure shows an error toast.** The inline message is drift: EXPERIENCE.md routes action failures to error toasts ("Save failed", "Action with no connection"). The change is a criterion on Story 3.54; the shared-helper refactor stays in action item 4.
2. **Security deferrals split by trigger.** `Secure` cookies in production are a criterion on Story 2.2 (`epics.md`), where HTTPS arrives. The REST path that lets a user change their own email or password is closed now as a small access fix (new action item 16; `deferred-work.md` entry marked decided). The sign-in timing leak is accepted for Phase 1 and revisited with NFR-5 if Phase 2 opens bookeh to others (`deferred-work.md`).
3. **Story 3.52 is split** (revised by decision 4). The new **Story 3.54 [K15] Epic 1 test and toast clean-up** runs first in Epic 3 (`epics.md`, `STORY-SLICING.md`, `sprint-status.yaml`). It is numbered last so the 17 existing references to "Story 3.52" and other Epic 3 numbers keep their meaning. It removes the e2e specs outside the spine, fixes the flash-cookie encoding with one round-trip test through Next's own serialiser (action item 1), and makes a failed sign-out show an error toast. Story 3.52 keeps scan-to-save and now states explicitly that Playwright runs on `bookeh_test`, the move deferred to it from Story 1.4.
4. **The spine stands: "Playwright covers only scan-to-save and shop check."** The seven Epic 1 e2e specs (admin, frontend, graphql, pwa, sections, settings, swipe: 45 tests) are out of bounds, and Story 3.54 removes them. A behaviour only one of them proved moves to a unit or integration test when it matters and can be tested there. The browser tests deferred from 1.16 (sign-in form) and 1.17 (toast provider), and the font-host check, are dropped rather than written. The intent behind the rule: keep tests to a functional minimum, written where they are necessary and make sense (action item 17).
5. **Unit and integration tests are trimmed too, and the intent goes into CLAUDE.md.** Story 3.54 trims the unit and integration suites to a functional minimum. Tests stay when they guard behaviour that can break in a way that matters, or when an Epic 1 acceptance criterion or the spine requires them. Tests that restate markup, class names, CSS or the manifest go. CLAUDE.md's Conventions now carry the rule, including that review findings which only ask for more tests need a reason. That completes action item 17.
