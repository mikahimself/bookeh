## Intent

**Problem:** A wishlist (7.1) has nothing on it. A wished-for Book needs its own row, never a copy or a copy status (FR-38, AD-8), owned by one user and pointing only at that user's list and Person and at a Book the user may read.

**Approach:** Add a private `wishlist-entries` collection on the `loans` / `copies` pattern: `ownerField()`, `wishlist` and optional `forPerson` as `ownedRelation`, `book` as `readableRelation`, and `closedAt` (empty while open), with `ownerAccess`. Register it, commit the generated migration and types, and prove the access and foreign-id rules with a two-user-plus-admin integration test.

## Boundaries & Constraints

**Always:**
- `ownerAccess` (AD-1, AD-2): read, update and delete are `owner = current user` for every role, the admin included; create is any signed-in user.
- `ownedRelation('wishlists', { name: 'wishlist', required: true })`, `ownedRelation('people', { name: 'forPerson' })`, `readableRelation('books', { name: 'book', required: true })` from `src/fields/relation.ts` (AD-17).
- `closedAt` is an optional `date` field holding an instant (time of day kept): not the `calendarDate` noon-UTC helper of `Loans.ts`.
- Generated interface `WishlistEntry` (set with `typescript.interface`); labels Wishlist entry / Wishlist entries; admin group 'My data'.
- No uniqueness constraint: the same Book may be on a list more than once, open or closed (AD-8).
- The migration is generated by `payload migrate:create wishlist_entries` from a database at `20261027_115654_wishlists`, and `src/payload-types.ts` is regenerated, both in the same commit (AD-13).

**Never:**
- No `lib/wishlists` service, no `closeEntriesForBook` / `closeEntry` / `setEntryRecipient` / `removeEntry`, no `saveEntry`, no holdings or `requireOwnBook` change (7.3), no `PersonUse` / `PERSON_IN_USE` change (7.4), no screens, actions or open-entry counts.
- No status field, no "closed as bought/ordered" field: the spine names `closedAt` only.
- No hook beyond what the field helpers carry; no new access or field helper; no ARCHITECTURE-SPINE.md change (AD-1, AD-8, the naming table and the F7 row already name `wishlist-entries` / `collections/WishlistEntries`).
- No hand-edit of generated foreign keys. The restrict-references / cascade-owners rule is retro item `epic-6-retro-item-66`, one migration over every collection; this table joins that set.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Create own | A creates `{ owner: B.id, wishlist: A's list, book: shared }` | Saved with `owner = A`, `forPerson` empty, `closedAt` empty; A finds it by id and by `find` | — |
| With recipient, closed | A creates with A's Person, then updates `closedAt` to an instant | Saved; `closedAt` keeps the instant as sent | — |
| Same Book twice | A creates two entries for the same Book on the same list | Both saved, distinct ids | — |
| Foreign list | A creates with B's wishlist | Rejected on path `wishlist`; no row | `ValidationError` |
| Foreign Person | A creates with B's Person | Rejected on path `forPerson`; no row | `ValidationError` |
| Foreign private Book | B creates with A's private Book; A with own private Book | B rejected on path `book`; A saved | `ValidationError` |
| Foreign read / write | B or admin reads, updates (`closedAt`) or deletes A's entry | `find` empty, `findByID` throws; writes refused; row unchanged | `NotFound` / `Forbidden` |
| Missing required | No `wishlist` or no `book` | Rejected on that path | `ValidationError` |

## Design Notes

**`closedAt` is an instant.** It records when the entry was closed (bought/ordered), not a calendar day the user picks, so it stays a plain timestamp; `Loans.ts`'s noon-UTC rule is for user-chosen dates.

**Foreign keys.** The generator writes `ON DELETE set null` on `owner_id`, `wishlist_id`, `book_id` and `for_person_id`, with `wishlist_id` and `book_id` NOT NULL. Deleting a wishlist through the back office therefore fails on a not-null violation while it has entries; `lib/wishlists` (7.5) deletes entries first, and item 66 sets the final rule. Recorded as a residual risk, not hand-edited.

**Production-dump check.** The migration creates a new table and adds a nullable column to `payload_locked_documents_rels`; existing rows are untouched.
