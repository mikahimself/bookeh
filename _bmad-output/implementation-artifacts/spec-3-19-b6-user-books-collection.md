## Intent

**Problem:** A user's edits to a shared Book, their read flag and their rating have no home. `bookFields.ts` (3.14) already declares the overridable set and `overrideFields()`, and `ownerField()` / `readableRelation()` (3.11) exist, but no collection assembles them into the one-row-per-owner-and-Book override layer that `EffectiveBook` (B8) and `upsertUserBook` (B9) will read and write.

**Approach:** Add the `user-books` private collection: `ownerField()`, a required `book` readable relation, `overrideFields()`, a validated `overridden` name list, `read`, `rating` and `ratedAt`, under a reusable owner-scoped access object, with `(owner, book)` unique in the database from the first migration. Commit the migration and regenerated types, and add a two-user access and constraint test.

## Boundaries & Constraints

**Always:**
- Slug `user-books`, file `src/collections/UserBooks.ts`. Fields in this order: `ownerField()`; `readableRelation('books', { name: 'book', required: true })`; `...overrideFields()`; `overriddenField()`; `read` (checkbox, `defaultValue: false`); `rating` (number, `min: 1`, `max: 5`, optional, `admin.step: 1`); `ratedAt` (date, optional).
- `overriddenField()` lives in `src/fields/bookFields.ts` next to `OVERRIDABLE_BOOK_FIELDS`: a `json` field named `overridden`, `defaultValue: []`, not `required` (Payload's json validator counts `[]` as empty). Its `validate` accepts null/undefined or an array whose every entry is a member of `OVERRIDABLE_BOOK_FIELDS`, with no duplicates, and otherwise returns `req.t('validation:invalidInput')`. Its `typescriptSchema` emits an array of that enum so `UserBook['overridden']` is typed.
- Access is a new `ownerAccess` in `src/access/owner.ts`: `create` = signed in; `read`, `update` and `delete` = `{ owner: { equals: user.id } }` for any signed-in user, admin included, and `false` signed out (AD-1). No role branch anywhere in it.
- AD-19: `indexes: [{ fields: ['owner', 'book'], unique: true }]` on the collection config, so the unique index is in the migration that creates the table.
- Admin: `group: 'Library'`, `defaultColumns: ['book', 'owner', 'read', 'rating']`.
- Register `UserBooks` in `payload.config.ts` collections, alphabetical (`Authors, Books, Genres, Media, Series, UserBooks, Users`).
- Move `randomIsbn` from `tests/int/books.int.spec.ts` to `tests/helpers/isbn.ts` and import it in both specs; the test's shared Books carry a fresh random ISBN like every other test row.

**Never:**
- No `lib/books` service, `EffectiveBook`, `upsertUserBook`, `setRead` or any reader of this collection (B8, B9, E24).
- No `tags` field (G1, Epic 9) and no `copies` (B7).
- No hook keeping `rating` and `ratedAt` in step, no hook freezing `book` after create, no rule that the Book is shared: the single writer `upsertUserBook()` owns those (AD-6, AD-18).
- No change to `overrideFields()`, `ownerField()`, `readableRelation()` or `catalogueAccess`.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Own row | A creates a row through the gateway for a shared Book with `title`, `overridden: ['title']`, `read: true`, `rating: 4`, `ratedAt` | Saved; `owner` = A whatever the input said | — |
| Read scope | A's row exists | A's `find` and `findByID` return it. B's and the admin's `find` by its id return no docs; their `findByID` fails | `NotFound` |
| Foreign write | B updates or deletes A's row by id through the gateway | Nothing changes; the admin gets the same | `NotFound` |
| Foreign private Book | A's row pointing at B's private Book | Not saved, error path `book` | `ValidationError` |
| Own private Book | A's row pointing at A's own private Book | Saved | — |
| One row per owner and Book | A creates a second row for the same Book; B creates one for that Book | A's second fails; B's is saved | `ValidationError` |
| Bad values | `overridden: ['isbn13']`, `overridden: ['title', 'title']`, `rating: 6` or `rating: 0` | Not saved, error path `overridden` / `rating` | `ValidationError` |
| Signed out | A create with no `req.user` through the Local API with access on | Refused | `Forbidden` |

## Design Notes

`ownerAccess` is a plain object, not a factory: every private collection uses the same four rules with no parameters (AD-1), and the copies, locations, people and tags stories reuse it as is.

`overridden` is validated at the field so a back-office edit cannot store a name that `EffectiveBook` (B8) would never apply; what the list means (a listed field's stored value is the override, empty meaning cleared) stays with `upsertUserBook()` and the reader.

```ts
const own: Access = ({ req: { user } }) => (user ? { owner: { equals: user.id } } : false)
const signedIn: Access = ({ req: { user } }) => Boolean(user)
export const ownerAccess = { create: signedIn, read: own, update: own, delete: own } satisfies …
```
