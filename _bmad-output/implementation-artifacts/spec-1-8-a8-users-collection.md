## Intent

**Problem:** `users` is still the Payload template stub: no roles, display name or language, default access (any signed-in user reads and updates every user, and any user enters `/admin`), and 2-hour sessions. Every later Epic 1 story (seed, gateway, i18n, profile) needs the real account shape, and migration history (AD-13) starts here.

**Approach:** Rewrite `src/collections/Users.ts` with `roles`, `displayName` and `language`, access declared for every operation through `isAdmin`, admin-only `roles` writes, admin-only `/admin`, and `tokenExpiration` 30 days. Commit the first migration (the whole current schema) and the regenerated `payload-types.ts`, with a two-user access test.

## Boundaries & Constraints

**Always:** Roles are tested only through `isAdmin` from `@/access/roles` (the lint rule bans inline reads). Local strategy and server-side sessions stay on (`useSessions` default). Tests run on `bookeh_test` via `createUser()` / `as(user)` and never delete rows. The migration is generated by `payload migrate:create`, never hand-written, and never applied to a dev database.

**Never:** No `profileVisibility` / `collectionVisibility` (Story 1.24), no `defaultLocation` (Epic 3), no seed (1.10), no `lib/account` or trimming/NFC of `displayName` (1.22 owns the profile boundary), no `prodMigrations` wiring (Epic 2), no CI migration check (1.9). No email adapter, invite or reset flow.

## Design Notes

- Admin may update any user: `roles` "writable only by admin" is meaningless unless admin can update other users' documents. Users are not private data (FR-48).
- `unlock` is declared too: Payload's default lets any signed-in user unlock any account after failed logins (`maxLoginAttempts` 5).
- Access functions stay inline in `Users.ts`: only `users` uses self-access; a shared where-helper waits for AD-1's owner access.
- `forgot-password` stays reachable over REST with no email adapter (token only in the server log); token-link resets (FR-5) and their rate limit belong to the story that builds resets.
